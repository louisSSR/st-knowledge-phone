# 知识来源与原文检索约定

掌上知库负责准确查找成熟来源、展示可追溯的原文，并让读者沿来源链接理解名词。v0.3 按用户确认的方向，默认联网检索，成功读过的正文缓存到本地；ZIM 为可选离线来源。不以逐篇采集、原创百科或模型总结填充资料数量。

当前在线实现仅接入中文维基百科，不能因此声称已覆盖所有主题、来源或名词。本文同时约束后续来源接入；未实现的能力不能仅凭这份政策宣称通过验收。旧演示包、TextExtracts 摘录和采集测速仅保留作开发证据。

## 来源身份、正文与许可

- 来源须有可核实的维护主体、稳定条目标识、原始出处及阅读或复用许可。优先使用来源官方接口或官方资料分发，不把少量人工摘录称为“大库”。
- 阅读内容须对应具体页面或文档。能固定版本时保留修订号、快照日期或校验信息；无法证明历史版本时明确标注，不编造版本绑定。
- 保留可呈现的章节、列表、表格、注释、公式和链接。阅读器改变排版、停用互动或省略资源时须说明，并提供原始出处；不能将受限阅读视图称为原网站完整副本。
- 标题、维护者、地址、版本依据、获取时间、许可与归因分别保存，不在无依据时补填。来源自己的文字不标为插件原创。
- 中文维基百科正文标明来源的 CC BY-SA 4.0，并提供具体修订链接；代码的 GPL-3.0-or-later 不改变正文、ZIM、图片或其他导入资料的原有版权及许可。

正式离线库、在线检索和已读缓存必须分别标明。在线搜索结果或外部网页链接不是已安装的离线资料；已读缓存是有限页面集合，不是百科全库。资料规模、覆盖语言和离线完整性以实际内容为准。

## 在线检索与推荐

当前搜索直接访问中文维基百科官方 Action API，仅传输用户提交的查询词、打开的词条标题与接口参数，不传输聊天、聊天身份、历史记录、日期或地点。来自聊天的关键词只生成本地可点击入口；点击后才把该词作为查询提交，不能在聊天事件中自动搜索或预取。

检索使用来源的全文搜索、标题与重定向核对，最多展示 12 条结果，精确匹配优先。可按规则截取短问句中的查询词，但不调用 LLM 生成答案或补全知识。没有命中时说明没有结果，不创作一篇说明代替来源。来源自身的错误、缺漏或检索排序也不能视为已由本项目校正。

结果中的短片段来自检索接口，必须与正文区分。打开结果后请求对应的来源正文 HTML，不能用摘要、纯文本摘录或多来源拼接冒充正文。中文维基百科词条内链接继续访问该来源，目标缺失、读取失败或外部跳转须可辨认；不能用原创名词解释替代缺失目标。每次内部导航可能取得目标的当前版本，不保证不同词条处于同一历史时刻。

在线阅读保留可呈现的表格和 MathML；图片、外部样式、脚本、音视频与互动组件不自动下载或执行。需要这些内容时由用户打开来源网页，原文出处和修订链接始终保留。外部 HTTPS 链接只在用户点击后打开。

## 缓存与失败语义

仅成功读取的正文缓存到扩展已有 IndexedDB，保存 HTML、标题及别名、来源、修订号、地址和获取时间。最多 20 页、总计 10 MiB，按成功获取顺序淘汰较旧页面。页面过大或存储失败时照常显示已读取正文，并明确说明未能缓存；不预抓取未读链接或批量下载百科。

缓存按浏览器扩展数据库共享，不按聊天复制。收藏和历史按聊天保存，但收藏不会阻止正文缓存被淘汰。直接读取缓存无需联网；缓存页面保持原获取时间，不因再次阅读而变成最新版本。

网络查询失败时明确说明原因，并只将实际匹配的缓存作为「已读原文缓存」呈现。缓存没有目标正文时不能承诺断网可读。网络或地区限制不能靠文档承诺解决，扩展不暗中切换第三方镜像、代理或付费服务。

## 离线资料与时间线

ZIM 由用户主动选择本地完整文件，按需读取，不将整个文件复制入浏览器数据库。当前一次连接一个库；刷新后重新选择同一文件，无需重新下载。中文维基教科书 99 MB 样本的成功读取不能证明百科覆盖、所有条目质量或 14 GB 整库性能。

默认在线科普查阅的是当前资料，明确提示「未按剧情年代核验」，与离线剧情模式分开。在线收藏和缓存也不能自动获得历史资格。事件发生时间、页面更新时间、获取时间和当前修订号，均不自动证明整篇资料在剧情日期已经可知。

离线模式继续按已有日期和地点约束过滤。严格时间线需要有依据的可知日期或历史版本；ZIM 暂以文件名快照月份的月末作保守资格判断，并明确这不是逐条历史核验。没有日期的 ZIM 不能用于严格剧情。原文内部目标也须执行对应离线时间资格检查。

## 正式来源验收

具体来源接入须分别提供证据：接口或文件真实可用；来源及许可准确；原标题、重定向与典型名词可检索；正文和修订可追溯；表格、注释、公式及词条链接符合声明；缺失目标、联网失败与缓存淘汰行为明确；所承诺的断网阅读确实在断网条件下可用。

官方 API 文档、一次命令行响应、自动测试、浏览器 CORS、真实酒馆运行及用户验收是不同证据。ZIM 受控超时注入只能证明恢复行为，不能证明用户自然超时根因已经定位；历史版本通过也不能证明新版通过。
