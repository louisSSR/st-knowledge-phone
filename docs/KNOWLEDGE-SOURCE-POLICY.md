# 知识来源与原文检索约定

掌上知库的正式资料路线是：接入已有的成熟知识库，准确找到有关条目，并让读者沿出处阅读原文及原文中的名词链接。主题不限于某一种牌戏，也不由本项目另写一套科普内容来填充数量。

本文是正式资料接入与验收要求，不代表所有接入能力已经完成。旧版演示包、TextExtracts 摘录和采集测速记录继续保留作开发证据，不能代替成熟库接入。

## 什么可以成为正式来源

- 来源有明确的维护主体、稳定条目标识、可追溯出处及适用的阅读或复用许可。以来源自身的完整资料集、官方分发或官方检索接口为接入对象，不把人工挑出的少量摘录称为“大库”。
- 阅读内容可对应具体页面或文档；能够固定版本时保留版本号、修订号或快照日期和校验信息。只能访问当前网页时明确写“当前页面，未固定历史版本”，不编造版本绑定。
- 默认保留原文的章节、列表、表格、注释、公式及链接所表达的信息。某种格式暂不能可靠呈现时，提供原始出处或提示该内容不可用；不得声称已展示完整原文。
- 来源元数据与正文分开保存。标题、作者或维护者、原始地址、版本依据、获取时间、许可和必要归因可被读者查看，不在无依据时补填。

正式离线库与在线原文入口需要分别标明：离线库必须有实际可读取的本地内容与索引；网页链接或在线搜索不能标为已离线安装。数据规模、覆盖语言、离线完整性和检索性能均以实际接入与测试结果为准。

## 检索、推荐与正文

检索和推荐依据可检查的规则、索引与来源元数据，不调用 LLM 生成知识答案。优先匹配标题、来源别名、重定向及正文词语，并让读者区分精确命中、消歧义选择和相关条目。没有命中时说明缺少结果，不能创作一篇答案补上。

结果卡片可以显示来自原文的短片段，必须明确它只是检索片段；点击结果后进入对应原文或可核实的原文阅读入口。摘要、纯文本摘录和项目改写不能冒充全文，不能将若干来源拼接成一篇“原文”。

原文中的名词链接应尽量导航到同一来源、同一资料版本的目标条目，保留锚点、返回路径与来源身份。消歧义、重定向、目标缺失和跨来源跳转都应明确呈现；离线缺失的目标不得用原创说明冒充已收录内容。外部原文链接须标明将打开外部网页，不能装作本地条目。

本项目不撰写规则、常识、地点、新闻或商品资料作为正式知识供应，不用生成内容修补原文缺段。需要游戏玩法时准确检索成熟来源中的相关规则；需要其他知识时采用相同原则。

## 时间线与历史快照

今天取得的原文只能证明今天取得了该内容。事件发生时间、条目创建时间或同次查询观测到的修订号，不能自动证明整篇内容在历史剧情日期已经可知。

严格时间线只能使用有依据的历史版本或知识可知日期；版本不明时明确不可确认。现代来源可在用户选择的现代或自由查阅模式访问，但不能悄悄回填为过去可知。来源内链接也须重新检查目标版本和时间资格。

## 旧资料迁移

`packs/manifest.json` 是正式随附资料的推荐目录，目前为空。现有文件仍保留供回归测试、格式复现和既有安装查阅：

| 资料 ID | 定位 | 不可作出的声明 |
| --- | --- | --- |
| `knowledge-phone-original-demo` | 开发样本：原创桌规、虚构地点和时间线 fixture | 不是真实百科、官方规则或现实商家资料 |
| `wikipedia-zh-starter-*` | 历史实验：13 篇 TextExtracts 摘录 | 不是完整网页、成熟百科库或固定历史版本 |
| `wikipedia-zh-general-*` | 历史实验：92 篇 TextExtracts 摘录 | 不是完整网页、成熟百科库或固定历史版本 |

迁移应保留用户已经导入的包、收藏和阅读记录，不因目录调整自动删除或改写它们。已安装旧包应显示“开发样本”或“历史摘录”，退出正式来源的默认推荐与检索入口；仅在用户主动选择旧资料范围时继续查阅。来源原有署名与许可必须保留。未知第三方包不能仅因导入成功就获标“正式来源”。

`corpus/` 和采集脚本只保留为历史实验工具及测试基础设施。旧脚本的技术通过、速度成绩或真实宿主导入通过，都不能升级为“成熟库全文接入通过”。

## 正式来源验收

接入具体成熟库时须逐项提供证据：数据或接口真实存在且可用；来源和许可准确；原标题、别名及消歧义可检索；阅读内容与原文对应；表格、注释和链接没有被悄悄丢弃；来源内导航与缺失目标行为正确；版本和时间线限制准确；所承诺的离线行为确实断网可用。容量与响应速度按实际资料规模测量，不能沿用小样本结论。
