# 现成知识库的来源与检索验收

本项目负责精确搜索、相关推荐和原文浏览。正式知识来源应使用已有资料库的原文、标题、链接和许可；不再把自行改写的短文、删减规则或虚构示例当作百科内容。增加资料覆盖的主线是挂载现成归档，不是维护逐篇采集清单。

下载镜像必须由官方 Metalink 列出，下载后比对长度与官方 SHA-256。证据文件 `evidence/zim/source-receipt.json` 记录实际下载时间、镜像、响应长度和本地散列；归档及本机测试日志不提交 Git。

## 数据源覆盖和时间边界

2026-09-20 检查的 [Kiwix 官方 Wikipedia 目录](https://download.kiwix.org/zim/wikipedia/)提供中文百科整库和篮球、化学、计算机、地理、历史、数学、医学、分子细胞、电影、物理等主题归档。本次目录中没有名称为中文扑克、棋牌或斗地主的独立主题包；不能据此断言整库没有这些文章。

中文维基教科书是另一种资料源，其内容覆盖不等于维基百科。下载一个较小整库可验证引擎和阅读流程，但不能因为文件名是中文就保证它包含斗地主。任何查询必须以实际档案的命中与原文为准；未覆盖时应明确“当前资料库未找到”，并允许用户切换资料源或自主打开原站搜索。

2026 年归档是当时抓取的快照，并不证明每个知识点于 2026 年首次公开，也不能冒充 2008 年可知的内容。归档日期只用作版本与新旧提示；历史角色的严格可知时间仍需有据可查的历史版本。不要从篇名、事件发生年份或主题古老程度猜测可知时间。

## 原有资料为什么只能保留为测试材料

`packs/original-demo.pack.json` 自称“原创演示包”，17 条里有六种牌戏、虚构商店/服饰及日期过滤 fixture。六种牌戏均没有外部来源 URL；正文只有约 255–394 个字符。这样的数据能检验界面流程，不能满足用户学习真实知识的目标。

- 斗地主条目明确省略飞机和复杂带牌，只让玩家自行约定特殊牌压制关系；没有完整名词解释、实际规则来源和可继续阅读的术语链接。
- 升级条目自行固定主花色和级牌，去掉底牌、对子、拖拉机和甩牌。它检验的是示例展示，不是对真实升级玩法的可靠介绍。
- 德州扑克、21 点、接龙与抽乌龟也被定义为简化演示；给短文标注“原创”不会补足规则出处、变体差异和上下文。
- 地点、店铺、服饰和时间线条目有意虚构，同样不能混入现实科普推荐。

已经采集的 92 篇维基百科文本虽保留出处，仍是小范围纯文本抽取；其中图片、部分模板、表格和公式可能缺失。它可作为旧格式的回归样本，不能代替完整知识库，也不应继续充当扩充资料的主要方案。详见[旧资料包处理说明](../packs/wikipedia-zh-general/README.md)。

## 必须用原文通过的检索契约

| 场景 | 通过条件 |
| --- | --- |
| 确切标题 | 匹配标题的结果优先出现，保留资料库名称、原始标题和归档版本 |
| 名词解释 | 命中原有词条或正文段落；没有词条时说明未找到，不生成“原创解释”填空 |
| 全文搜索 | 使用归档自身的全文索引；索引不存在时明确说明能力限制，不能把仅标题搜索标成全文检索 |
| 规则与例外 | 阅读原文的完整相关段落和章节，而不是人为缩成几句规则 |
| 推荐理由 | 展示题名、匹配片段或原文链接关系等可验证理由；推荐不替资料源编写事实 |
| 相关链接 | 保留原文章节和术语链接；能解析的库内链接在本地读取，跨库或缺失文章明确显示边界 |
| 无结果 | 不拿演示数据或模型杜撰内容冒充资料库命中 |
| 来源与许可 | 原文来源与许可可见，不将第三方资料标成项目原创；页面自己的引用继续可访问 |
| 离线 | 断网后已挂载归档仍可检索和打开原文，不全量导入浏览器 IndexedDB |
| 容量与性能 | 单独记录归档字节数、实际检索延迟和阅读所需内存；小档验证不能代替大档性能证据 |

斗地主是质量问题的例子，而非唯一修补目标。以后可以把“斗地主／叫牌／顺子／连对／飞机／炸弹／王炸／春天”、扑克的“盲注／公共牌／边池”，以及其他领域的概念与关联词作为覆盖检查集；它们只是待验查询，不是断言本次样本包含的条目。测试报告必须逐项记录实际命中、缺失和原文链接，不能用新写摘要来让测试看起来通过。
