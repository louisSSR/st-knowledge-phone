## 发现并修复

0.1.1 声明 `clean` hook，却仅关闭界面。实际点击「Clean extension data」并刷新后，`content=41 / entries=41 / indexes=3 / manifests=3 / values=2` 完全未变。

0.1.2 的清理钩子先释放手机、监听与 Worker，再等待一个 IndexedDB 写事务清空本扩展的所有 stores，包括偏好、收藏、历史和聊天上下文；提交完成才返回。真实重验五项计数均为 0，并能重新导入资料。

`delete` hook 仍只释放运行实例，是否同时清除资料由宿主删除弹窗的清理复选框决定。未改变其他库或酒馆聊天存储。宿主自身会捕获 hook 错误，不能只根据其成功提示判断清理结果。

复看截图时还发现窄屏上半部出屏：宿主给零高 `html` 设置 transform，使原先 `fixed + inset:0` 的背景层高度成为 0。早期检查只覆盖横向溢出，因此漏检了垂直位置。修复后入口容器和背景层使用明确的视口宽高；关闭状态下根容器透传点击。真实 390×844、320×568、1440×1000 均重新检查面板、标题、关闭按钮与导航边界，并实际点击关闭、重新打开、酒馆输入框。新增的浏览器回归用例保留了零高、带 transform 的宿主条件。

新增 8 项清理回归测试，自动测试总计 **72/72 通过**；独立浏览器回归 **21/21 通过**，构建与 manifest 校验通过。构建报告的版本号也改为读取项目版本，修正旧的硬编码值。完整截图、清理和布局的前后数据、测试输出与 22 项实机运行回执留在本地 `evidence/real-host/`，未发布原环境日志或私有配置。
